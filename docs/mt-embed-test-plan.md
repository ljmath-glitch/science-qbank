## 二、測試項目

每項請記錄：✅ 通過／❌ 失敗（附截圖、步驟）。

### A. 單題圖片（題目編輯器）
| # | 步驟 | 預期結果 | 結果 |
|---|---|---|---|
| A1 | 開一題測試題 → 圖片區按「📐 插入繪圖」→ 登入 → 選一個工具（例如三角形）→ 調整 → 按「完成」 | 題目圖片區多一張圖；此時還沒存檔 | |
| A2 | 按題目的「儲存」 | 存檔成功；圖片正常顯示、比例正確 | |
| A3 | 重新整理頁面，打開同一題 | 圖還在，且有「編輯繪圖」按鈕 | |
| A4 | 按「編輯繪圖」 | 工具打開時就是**原本那張圖**（不用重畫） | |
| A5 | 改一個數值（例如邊長）→「完成」→ 儲存 | 圖更新；圖片的**大小、對齊、位置不變**；同題其他圖片不受影響、順序不變 | |
| A6 | 再按「編輯繪圖」→ 改東西 → 按「取消」 | 原圖完全沒變 | |
| A7 | 「插入繪圖」→ 直接關掉視窗（右上角／Esc） | 沒有新增任何圖 | |
| A8 | 一題原本就有的**舊圖片**（不是工具畫的） | 照常顯示；沒有「編輯繪圖」；原本的圖片功能（橡皮擦等）照常 | |

## 三、已知限制（不用回報為錯誤）
1. 等待時間：開工具後最多等 **10 分鐘**（含登入）；整個編輯過程最多 **60 分鐘**，超過自動取消、不改資料。
2. 回編後，舊的 PNG 檔會留在 Supabase Storage（跟現有的橡皮擦一樣不會刪）。
3. 對「工具畫的圖」用橡皮擦擦過，之後再按「編輯繪圖」會依原設定重畫，擦掉的內容會回來。
4. 開發者工具的 Console 可能出現一行 MathLive 的 `postMessage target origin mismatch` 訊息，無害。

| 項目 | 位置 |
|---|---|
| 題庫分支 | `ljmath-glitch/science-qbank` → `claude/mt-embed-integration` |

| 題庫端說明與 `imgs[].mt` 資料格式 | 題庫 repo：`docs/mt-embed.md`、`CLAUDE.md` §6.15 |

圖片在 `questions.imgs` 中的格式：
```js
{ src: '公開 URL', width, align, x?, y?, …原有欄位,
  mt: { v: 1, figureId, config /* 工具回傳，原樣保存 */, widthCm, pxW, pxH } }
```

**目前部署狀態**：題庫暫時連到工具整合分支的預覽網址（使用者已確認）；工具正式站的 `/mt-embed.html` 尚未部署。工具端正式部署並通過實測後，再把 `mt-embed-client.js` 的 `TOOL_ORIGIN_OVERRIDE` 改回 `''`。測試資料仍會寫入正式 Supabase，請只使用測試題。
