## 目標（使用者原話重點）
- 題庫要「每個功能乾淨、沒有錯誤」，老師出卷時不用再修圖、改字。
- 系統本來就給老師審核：**入庫時審一次**（並排看原卷與結果），出卷時不用再審。
- 要貼近 aixwang.dev 的題庫系統設計（待審區、四段審核、缺項擋啟用、並排審核），保留我們好的部分（翰林架構分類 `chapter-map`、茲茲數學工具、組卷精靈、題組、去筆跡、本機 OCR）。
- 圖片是大問題：要有「圖片狀態」；少數壞圖才人工重置，期望人工不是多數（D 級目標 ≤10%，待實測）。
- 沒有 API 預算：Gemini 走訂閱（`agy`，經 `tools/agy_bridge.cjs`），不生成考卷圖，只裁切、放大、清底、看圖檢查。

## 已定案的設計（細節在規格書）
- 流程：取得 → 前處理（本機）→ 品質關（自動）→ 待審區 → 人工審核 → 正式題庫（active）→ 組卷 → 輸出。
- 四段審核狀態：題幹／答案／詳解／圖片；啟用需全過。圖片分 A/B/C/D 級。
- 人工六個佇列：圖片重置、圖片審核、題幹審核、答案與詳解、分類確認、重複與回報。
- 新頁面 `review.html`（不塞進 11,000 行的 `index.html`）；`doImport()` 改寫入待審區；組卷只列 active。
- 資料庫只加欄位／表，不刪舊資料；遷移前先備份。
- 不採用 Laravel/Dcat Admin（技術棧不符、無預算）；只借鏡其表格／批次／RBAC 的做法。
