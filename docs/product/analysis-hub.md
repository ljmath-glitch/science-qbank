# 考題分析中心（analysis.html）設計與評估

依據 PRD（自然科命題趨勢分析與智慧課程規劃系統）與**實際題庫**（Supabase `questions`，2026-10-19 盤點）整理。

## 1. 題庫實況（以實際資料為準）

- 7,029 題（不含題組文章 1,082 筆 passage 列）、177 份考卷、25 個來源（學校／出版社）。
- 沒有 `exams` 表：`exam` 只是 `questions` 上的文字欄；學校在 `school` 欄；年級、學期、段考次、考試類型都**藏在 exam 名稱字串裡**（`index.html` `precompute()` 現場解析）。
- exam 名稱格式不一致，同一份卷有多種寫法：`天母國中-八年級-111-上學期-第三次段考`、`…-111上-第一次段考`、`…-第三次段考-理化`；有些名稱只有 passage 沒有題目（0 題），有些名稱標「生物」但 field 是理化。
- 沒有 `points`（配分）欄；沒有題目↔知識點的關聯表：`kp` 是一個文字欄，**多個知識點用「、」串在一起**（理化 54%、生物 56%、地科 45% 的題目有多個）。
- `kp` 同時混有「學習內容」代碼（Ba-Ⅳ-1、INa-Ⅴc-1、EEd-Ⅴc-1）與少量「學習表現」代碼（ti-Ⅳ-1、tm-Ⅳ-1、po…，探究能力；實測約 115 筆，占知識點項目的 0.8%）；章節統計必須只用學習內容代碼，並把學習表現另列。
- 難度三分數：step／mem／con 各 1~3，0＝未評。**45% 的理化題是 2/2/2（疑似預設值）**，學測地科幾乎全是 2/2/2；總分 6 占 46%。難度圖若不處理會得到「幾乎全是中等」的假象。
- 資料缺口（實測，只算題目、不含題組文章列）：單元與知識點都沒有缺；答案缺 7 題（0.1%）；難度未評分 81 題（1.2%）；**疑似預設值 2/2/2 共 3,221 題（45.8%）**——這才是難度分析最大的問題。（先前版本誤把 1,082 筆題組文章列算進缺口，已更正。）

## 2. 對 PRD 的評估：需要修正的地方

1. **缺 Exams 實體是最大問題。** PRD 的「覆蓋率＝出現某知識點的有效試卷數 ÷ 有效試卷總數」需要可靠的「一份試卷」概念。解法：先在前端建立 `parseExam()`（把 exam 名稱正規化成 school／grade／year／term／period／category／subject 結構，並合併同一份卷的不同寫法），日後再決定是否落地成 `exams` 表。不先動資料庫，避免破壞既有功能。
2. **kp 要拆開、分類、標主次。** `parseKp()`：以「、」切開 → 抽出代碼 → 分「學習內容／學習表現」→ 第一個學習內容代碼＝主要知識點。支援兩種計數模式：主要知識點模式（每題算一次，用於章節比例與堂數）、知識點涉及模式（一題可多計，用於關聯與搜題），**兩者不得混用**，圖表標題必須標示目前模式。
3. **難度要標「疑似預設值」。** 2/2/2 標 `defaultSuspect`，難度分析預設把它和「已評分」分開顯示，並在頁面顯示「N% 的題目難度尚未實際評分，難度圖僅供參考」。另外「結構難度≠答對率」要寫在圖表說明上。
4. **配分沒有就不要假裝有。** 全部以「題數」統計並明示；`points` 欄位列為 Phase 3 新增。
5. **跨來源權重。** 預設「每份有效試卷等權」計算占比，而不是題數合併（避免 50 份模擬考淹沒 10 份會考）；跨類別比較時再依類別分層。
6. **不完整試卷。** 以每卷題數與 passage-only 判斷：題數少於門檻（預設 15，可調）或 0 題的卷標為「不完整」，預設不納入占比與覆蓋率（有開關），並在頁面列出被排除的卷。
7. **重複題。** 先做「疑似重複」偵測（摘要＋答案＋知識點相同且跨卷），只標記與計數、不自動刪除。
8. **歷史統計 ≠ 預測。** 只輸出歷史出題率、近期出題率、覆蓋率與 Wilson 95% 信賴區間；樣本不足（有效卷 < 5 或題數 < 20）標「樣本不足」；Phase 4 才考慮模型。
9. **教材版本對應。** 用課綱代碼當跨版本的共同語言；各版本的單元名稱留在 `CurriculumMappings`（先以 `syllabus_doc` 內的設定表與 syllabus.js 實作，不新增資料表）。
10. **不值得優先做的：** 命題機率預測、學生弱點（無答題資料）、自動選題演算法（先做「從統計格子鑽取到題目並送進組卷」即可）。複習優先指數中的 W（弱點）在沒有答題資料時**不設假值**，改為重新正規化其餘三項。

## 3. 架構

- 單頁應用 `analysis.html`（純靜態、與現有站台同風格）：左側導覽（8 個模組，hash 路由 `#overview`…）＋頂部全域篩選＋中央分析區＋右側題目抽屜。
- 共用資料層 `analysis-core.js`（純函式，瀏覽器與 node 兩用，`tools/test_analysis_core.cjs` 測試）：
  `parseExam`、`parseKp`、`difficulty`、`buildExams`、`filterQuestions`、`shares`、`coverage`、`trend`、`wilson`、`compare`、`flagDuplicates`。
- 資料載入：只抓分析欄位（不含 q／sol／imgs），分頁抓取 + `sessionStorage` 快取 10 分鐘（約 1.5 MB）。
- 分析結果必須可追溯：每個統計格子都能回傳其題目 id 清單，點擊後在右側抽屜列出題目（交接組卷沿用 `cp_picks` 機制）。
- 首頁 `home.html` 新增「考題分析」區塊，8 個模組各一張入口卡（連到 `analysis.html#模組名`）；舊的 `analytics.html` 保留。先前獨立的 `course-plan.html`（課程規劃儀表板）已依使用者要求刪除，其 9 堂課規劃改由模組 06（智慧課程規劃，Phase 3）重做。

## 5. 階段

1. **Phase 1a**：`analysis-core.js` + 測試（本文件 §6 的情境）。
2. **Phase 1b**：analysis.html 外殼＋全域篩選＋模組 01、08＋首頁入口。
3. **Phase 1c**：模組 02、04、07（章節比例／趨勢／學校比較／難度題型／鑽取抽屜）。
4. **Phase 2**：模組 03、05（熱力圖、覆蓋率、模考對大考）。
5. **Phase 3**：模組 06（堂數分配演算法）、配分欄位。
6. **Phase 4**：學生答題資料、命題機率估計（需回測）。

## 6. 統計驗證情境（測試檔必須涵蓋）

同題多知識點（兩種計數模式）、部分試卷、重複題、不同年度範圍不同（共同範圍模式）、學校卷數不同（等權）、無題章節、未完成難度、同時選多校、不同教材版本章節名稱不同、exam 名稱多種寫法合併。
