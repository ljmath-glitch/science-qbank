# 老師匯入與管理者清理：工作流程規劃

原則：老師和管理者的所有操作都在使用者介面完成；AI 助手在後台用 SQL 做大量自動修改，但每一批都要先備份、先預覽、經管理者在介面確認後才生效。

> 狀態標註：【已有】現在就能用；【待做】規格已定、尚未實作。

## 一、老師：匯入一份新考卷

### 匯入前（人工，約 5 分鐘）
1. 準備原卷 PDF（優先文字層 PDF，其次清晰掃描）；答案卷另附，不要混在同一檔。【已有】
2. 檔名寫清楚：學校＋學年＋學期＋考次＋科目。分類靠它。
3. 掃描卷先確認：不歪、不暗、沒有手寫壓住題目。手寫太多的卷，先請管理者做去筆跡。

### 匯入時
4. 在題庫頁用既有匯入功能上傳。【已有】
5. 【待做】匯入後題目進「待審區」，不直接進正式題庫；電腦先跑品質關，產出該卷報告：通過幾題、被擋幾題、缺圖幾題。

### 匯入後（人工，逐卷）
6. 看該卷報告。被擋比例超過 30% 的卷：不要逐題修，回報管理者，可能是原卷品質差。
7. 【待做】在審核頁對照原卷，只處理被標記的題：改字、補圖、確認答案，每題按「儲存並下一題」。
8. 【待做】題幹、答案、圖片三項都審核通過，該題才「啟用」，組卷才看得到。

### 老師要特別注意的錯誤類型
- 缺圖：題幹寫「如圖」但沒有圖。
- 選項不全：只有 A、B 或選項是空白。
- 答案不在選項範圍。
- 上下標被壓平：m/s² 變成 m/s2、3×10⁸ 變成 3×108。
- 閱讀測驗缺文章（目前品質關還抓不到）。
- 答案是否「正確」電腦驗證不了，只能靠老師看。

### 老師出卷時
- 紅色「⚠ 缺圖／選項不全」：這題有明確缺陷，換題或自己補。
- 黃色「⚠ 需人工確認」：用之前看一眼。
- 【待做】組卷精靈勾選「只選沒問題的題」，自動補題預設略過有問題的題。

## 二、管理者：清理過去有疑問的考卷

現況（2026-11-23 唯讀掃描，10,007 題、226 份考卷）：完全通過 8,211 題；被擋 1,781 題（缺圖 1,121、選項不全 576、答案不在範圍 160）；警示約 18 題；33 份考卷缺圖比例超過 30%。
決定：舊題「留著標記，不下架」。

### 管理者在介面做的事
| 步驟 | 內容 | 介面 |
|---|---|---|
| 1 | 看全部考卷的問題排行（由多到少） | 審核頁考卷清單【已有】 |
| 2 | 對 33 份高缺圖卷決定：補原卷、重新匯入、或接受 | 審核頁／題庫頁 |
| 3 | 看 AI 助手的批次修改預覽，按「同意」或「退回」 | 【待做】批次預覽頁 |
| 4 | 抽查自動修復結果（每批抽 20 題，對照原卷） | 審核頁 |
| 5 | 處理自動修不了的題（預計幾百題） | 審核頁 |
| 6 | 提供缺少的原卷與答案卷 | 由另一個 session 下載與整理 |

### AI 助手在後台做的事（SQL）
每一批依序：
1. **備份**：整張 `questions` 先完整匯出，記下時間與筆數。
2. **預覽**：列出將修改的題號、修改前後內容，存成報告給管理者。
3. **同意後才執行**，寫入 `question_log`（誰、何時、改了什麼）；原值存 `orig` 以便還原。
4. **驗收**：重跑品質關，對比修改前後數字，貼報告。
5. **可還原**：每批有批次編號，發現錯可整批退回。

可用 SQL 自動處理的項目（由安全到有風險）：
- 加上審核狀態欄位與舊題標記（遷移，只加不改內容）。
- 正規化欄位（圖表類型、題型、冊次）。
- 確定性文字修復：選項標號、版面雜訊（「試題結束」、頁碼）、已確認的壓平上下標。
- 補回遺失的圖片關聯（需對照原卷圖檔，非單純 SQL）。
- 對照答案卷修正答案（衝突者留人工）。

不可自動、必須人工：答案對錯、缺閱讀文章、圖是否切完整、重複題取捨。

### 管理者的決策關卡
1. 是否備份並執行資料庫遷移。
2. 每一批自動修改是否同意。
3. 是否 push 到正式站。
4. 某份考卷原卷太差時，是否放棄。

## 三、建議推進順序
1. 品質關與標記上線【已有】。
2. 組卷精靈「只選沒問題的題」【進行中】。
3. 備份＋遷移＋舊題標記（管理者同意後）。
4. 最糟一份考卷試跑自動修復，看修好幾成。
5. 批次預覽頁，讓管理者在介面同意或退回。
6. 全面修復，剩餘進人工佇列。
7. 匯入改走待審區，新卷不再產生新問題。
