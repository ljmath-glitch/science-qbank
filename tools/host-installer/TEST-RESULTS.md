# Windows 主機 2.0.2 測試紀錄

測試日期為 2026-11-16，使用實際 Windows 主機。

## 已通過

- 真正執行安裝腳本，建立獨立 Python 環境，安裝套件並下載 OCR 模型。
- 下載並初始化 PP-DocLayout v3 模型，大小約 124 MB。
- 註冊並啟動 OCR、AI 橋接、系統匣與更新排程。
- 實際切換舊版背景服務，確認健康回應的 installId 與新安裝目錄一致。
- 安裝視窗可見主機顯示名稱欄位，同時安裝時另一份會被互斥鎖擋下。
- 主機名稱設定可寫入並保留，Node.js 可讀取不含 BOM 的中文 JSON。
- 用本機考卷一頁測試 OCR，取得 1852 字元的結果。
- 使用同一筆 OCR 結果下載 Excel，HTTP 200，檔案可由 openpyxl 開啟，具備 23 欄與題目資料。
- 對同一頁執行自動切圖，成功傳回 4 個有影像與有效座標的圖塊。
- 真正的 .NET 更新程式讀取 GitHub 版本、下載 ZIP、校驗 SHA256、解壓縮並核對版本。
- 編譯、PowerShell 語法、更新版本比較、JSON 解析、SHA256 與 ZIP 路徑防護測試。

## 測試發現並修正

1. 舊版監督程序會重新占用 8787，安裝健康檢查曾誤認舊服務。改成辨認既有主機目錄、停止其監督程序與子程序，新版健康檢查必須符合安裝身分。移除依埠號任意停止程序的行為。
2. 發布包漏帶 buildlib.py 與 template.docx，導致 Excel API 回 500。補入與上游一致的 Windows 相容模組與範本，新增安裝前依賴檢查與套件入口回歸檢查。
3. 更新程式現在也核對 ZIP 內的程式與模型版本，避免版本資訊與套件不一致。

## 驗證範圍

測試使用的是尚有手寫內容的掃描頁，略過網頁清稿。OCR 分題與手寫干擾仍需人工核對，本紀錄不將可下載的 Excel 視為逐字轉錄正確。

尚未在全新、沒有任何前置工具的 Windows 電腦驗證 winget 安裝所有工具，也未強制演練通知點擊及切換失敗恢復。AI 橋接已啟動，本輪未呼叫付費 AI 分類。

重跑服務測試可執行 `node tools/host-installer/qbank-host-smoke.cjs <一頁PDF> <測試輸出目錄>`。必須先完成主機安裝並啟動 8787。
