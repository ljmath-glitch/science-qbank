# 改動後自動除錯 / 測試 SOP

**這是「監管模式」的品質關卡：使用者只看綠燈/紅燈，不自己測。任何改動在 push 前一定跑完這三關，紅燈就自己修、修完重跑，直到全綠才回報；不要把沒驗過的東西 push 上去。**

## 三關（依序，前一關過才做下一關）

### 關卡 1：語法檢查（必跑，快）
```
node .claude/skills/qbank-selftest/scripts/syntax_check.mjs
```
- 自動抽出每個 `*.html` 的 inline `<script>`（跳過 `src=` 外部檔）跑 `node --check`。
- 全過結束碼 0；有錯結束碼 1 並印出是哪個檔、錯在哪。
- 只想檢查某幾檔：`node .../syntax_check.mjs index.html analytics.html`。
- 紅燈處理：依錯誤訊息定位（常見：中文全形符號混入、括號/引號未閉合、模板字串 backtick 沒收）。修完再跑一次。

### 關卡 2：視覺驗證（改到畫面/CSS/版面時必跑）
- 用 **`qbank-visual-verify`** skill 的 `shot.cjs` 截圖：桌機（寬 1200～1360）＋手機（寬 390）各一張，改到哪頁就截哪頁。
- **一定要 stub 掉 `window.supabase` 並擋外部網路**（shot.cjs 已內建），否則畫面空白。要看有資料的畫面就餵 mock JSON。
- 用 Read 打開截好的 png 親眼看：版面有沒有爆、配色/字型/圓角是否符合 `qbank-design-system`、手機是否橫向溢出、元件有沒有重疊。
- 純邏輯（不碰畫面）的改動可跳過此關，但要在回報時講明「未動 UI，略過視覺驗證」。

### 關卡 3：邏輯 / 邊界檢查清單（動到 JS 邏輯時必想）
不是每項都要，但改到對應功能時務必逐項自問，能寫小測試就寫（放 scratchpad，不 commit）：
- **空值/缺欄**：資料某欄空白（如無答案、無題組ID、無圖）時會不會爆或誤判？（對照 `doImport` 的 flag 規則）
- **邊界數字**：難度 0 分 vs 滿分、題號非數字、題數 0、分頁最後一頁。
- **格式分支**：CSV 22 欄 vs 23 欄兩條路都要顧；LaTeX `$...$` 內含特殊字元。
- **重複/覆蓋**：同考試+領域+題號重匯是否正確 upsert 而非插重複、詳解/圖片是否被保留。
- **題組**：題組文章只該顯示一次、題號範圍算對、同組連動勾選。
- **多供應商**：詳解生成四家（Claude/Gemini/OpenAI/Ollama）的 dispatch 是否都改到（改詳解格式時三個進入點都要顧）。
- **手機 vs 桌機**：860px 斷點兩側行為。
- 能用 node 快速驗證的純函式（如 `calcDiff`、欄位解析），把該函式抽出來餵幾組輸入跑一下比對預期。

## 回報格式（給使用者看的「儀表板」）
跑完用這個格式回報，讓管理者一眼看懂：
```
🔍 自我檢查結果
關卡1 語法：✅ 7/7 檔通過
關卡2 視覺：✅ 桌機+手機各截圖確認，版面正常（或：⚠️ 手機版 X 溢出，已修）
關卡3 邏輯：✅ 已檢查 空值/題組/重複匯入 三項（或：❌ 發現 X，已修正並重跑關卡1）
結論：可以部署 / 尚有 X 待處理
```

## 與其他 skill 的關係
- 這關過了才輪到 **`deploy`** skill（push + 輪詢 Vercel）。selftest 是 deploy 的前置。
- 這個 skill 也被 SessionStart hook 用來在每次開 session 時跑關卡 1，讓 session 一開始就知道 repo 是不是乾淨的。

## 注意
- 截圖與臨時測試 `.cjs`/`.mjs` 放 scratchpad，**不要 commit 進 repo**。
- 這是純靜態站，沒有 npm test；「測試」就是上面三關，不要去找不存在的測試框架。
